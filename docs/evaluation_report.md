# Recommender Evaluation Report (offline proxy evaluation)

Generated by `scripts/run_evaluation.py` from the saved Adzuna files in `data/raw/` (no API calls, no database). Jobs after dropping content reposts: **75**. Random splits per persona: **50** (seeds 0..49).

> **This is NOT an evaluation against user feedback.** The project has zero users and zero interactions. Relevance below is a proxy derived from which Adzuna search returned a job. Numbers say how well each strategy recovers held-out jobs from the same search as a persona's seed jobs - nothing more.

## Methodology

1. **Persona** = one collection query in `data/raw/` (e.g. Data Analyst / Mumbai). Its **relevant set** is the jobs Adzuna returned for it (Scenario A) or for every query with the same search role (Scenario B).
2. The relevant set is split at random into **seed jobs** (stand-in for history) and **held-out jobs** (the labels). Seed jobs are removed from the candidate pool.
3. The **profile is built from seed jobs only**, by a fixed rule decided before running: skills present in >= 2 seed jobs; target role = search role; location = search city (Scenario A only); profile text = role + skill names (the same recipe as `profile_from_user`).
4. Each strategy ranks the candidate pool with the **production ranking code** (`recommender.ranking.rank_jobs`) and default weights (hybrid normalised: skill 0.41, content 0.35, role 0.12, location 0.07, popularity 0.06). Weights were NOT tuned on these results.
5. Metrics (binary relevance): Precision@K, Recall@K (denominator = held-out relevant jobs), NDCG@K, and **Diversity@K** = 1 - mean pairwise TF-IDF cosine similarity of job texts in the top K (higher = more varied lists; it measures variety, not quality).
6. Values are **mean ± std over all (persona x seed) trials**. Trials from one persona are not independent.
7. **Random** is a sanity floor, not a fifth strategy.
8. **Winner rule (fixed in advance):** a strategy is a clear winner only if it has the highest mean NDCG@10 of the four, is ahead of every other strategy in every persona, and the 95% paired-bootstrap CI of its advantage over the runner-up excludes 0. Otherwise: no clear winner.

## Limitations

- **Proxy, not feedback.** Relevance = "Adzuna returned this job for the persona's search". It is not a judgement that a job suits a person. No real or synthetic user preferences are used or claimed.
- **Circularity.** The query defines both the persona's role/location and the relevance label. In Scenario A, location is a near-perfect label proxy (each persona's relevant jobs are all in one city), so any location-aware strategy is advantaged and the Hybrid result partly reflects that. Scenario B removes location to reduce this, but role words still drive both profile and label.
- **Skill signal is weak and partly leaked.** Profile skills come from seed jobs of the same query, so skill overlap measures similarity to those jobs. Only ~1.7 skills are extracted per job (short snippets), so Skill-based ranks many jobs with a score of 0 and falls back to id order.
- **Tiny, narrow data.** ~75 deduplicated jobs, 4 queries (Data Analyst in Mumbai/Pune, Data Scientist in Bengaluru/Hyderabad; no other roles). Only 2 (Scenario B) or 4 (Scenario A) personas; repeating 50 random splits reduces split noise, NOT persona-sample size, so the CI understates uncertainty about generalisation.
- **Popularity is not personalised** and is only a recency percentile (no interaction counts exist), so it is a weak baseline by construction.
- **Content signal and the label share vocabulary** (job titles contain the search role), another source of circularity.
- **Diversity** is text-similarity based and is a property of the list, not its accuracy.
- **Behavioral personalization is NOT evaluated.** The project has zero real interactions, so the behavior signal is inactive here (dropped and the other weights renormalised); no claim is made about interaction-informed ranking quality.
- Results describe this collected sample only, not the Indian job market.
